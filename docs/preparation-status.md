## 范围与处理结果

公开源码在独立仓库中整理。原项目及其稳定版安装包保留；原开发历史、真实业务样本、私有测试记录和本机交付产物不进入公开仓库。

本轮完成的源码与文档整理包括：

- 以虚构的等长测试文字替换与业务有关的公司名称、示例流水标识和个人路径，保留测试几何及边界条件。
- 移除不再调用的模拟任务服务，把仍使用的共享类型移到领域模块；保留有调用方的兼容逻辑和回归测试。
- 重写使用、开发、贡献、安全与发布文档，明确当前功能、限制、模型下载和反馈方式。
- 增加发布文件扫描脚本，检查私有文件类型、个人路径、常见密钥格式和可选本地敏感词表。敏感词表本身不公开。
- 提供 Core 与 Ocr 两种 Windows x64 包的可重复构建流程：固定 Python 发行包、精确 wheel 版本及 SHA-256，附带私有 Python 3.12.14。
- 正式安装包仅使用随包解释器；资源缺失时显示中文启动错误。开发模式与正式包的解释器选择在文档中分别说明。
- 发布构建要求固定且干净的源码提交，并记录实际产物、工具版本和运行时清单，拒绝旧产物或构建中被修改的源码。
- 前端及 Rust 的 264 个依赖组件附带 471 份原始许可与通知文本；缺少文本或备用文本校验不匹配时停止构建，备用文件保留原始字节，避免 Git 换行转换使校验失效。

扫描是发布门槛的一部分，不能证明不存在所有敏感信息或安全缺陷。公开提交仍需人工复核，业务 PDF、任务数据库、缓存和日志始终不得提交。
