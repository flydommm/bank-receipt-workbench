# 上海银行普通回单模板身份修复

日期：2026-09-24。对应 0.1.48 远端复检发现的问题；本记录是源码工程验证，不代表新安装包或远端人工验收。

## 恢复点与问题

修复前已提交上一轮复检记录：`18aa3ac docs: record 0.1.48 remote targeted acceptance`。原 0.1.48 远端复检记录（历史资料已归档） 保留当时的真实结果。

SH-A 普通回单不能保存跨文件模板有两个可复现原因：

1. 回单编号位于居中标题上方，记账日期位于标题侧面。下一张回单的顶部文字被算成上一张正文，触发“正文跨过下一标题”的安全拦截，整页模板身份随之不可用。
2. 原生文字中的斜向“上海银行”水印虽已被解析器标记为水印，仍进入了行级银行抬头判断，把下一张的起点提前到上一张回单内部。

这两个原因与用户排除片段、确认特殊单证的先后顺序无关。

## 修复边界

- 使用可信的同一出具银行、相同标题、完整且唯一的编号/日期字段，以及跨栏重复的位置，识别围绕居中标题的顶部区域。
- 顶部区域内所有相交文字均须与页首第一栏对应。固定字段、同一行中明确配对的字段值、固定文案分别核验；无法归属的新增正文、缺字段、重复字段和位置冲突不能借此获得模板身份。
- 顶部区域最多检查 32 行，限制配对开销。
- 将经过核验的顶部固定字段位置纳入版式身份。日期、编号等具体值变化不影响匹配；顶部字段位置变化不能误用同一模板。
- 按解析器已有的水印结论，精确匹配文字及边界，避免水印重新进入银行抬头判断；不按区域重叠删除正文。
- 保留正文及图形跨界、未知银行、不同银行、不同凭证类型等既有拦截。不修改审核、排除、模板存储或停用逻辑，也不清理用户数据。

计算版本已包含受修改源码的哈希；新代码下需重新分析以取得新身份，无须清空数据库。

## 验证

新增 [顶部字段回归测试](../tests/test_receipt_heading_band.py) 13 项，覆盖正向识别、字段值变化、字段位置变化、水印、字段缺失/重复/错位、正文引用、两种跨界正文、交易对手银行不能充当出具银行，以及两个合成 PDF 间保存和复用模板。

最终关联回归 **456 项通过**（73.15 秒），涵盖上述新增测试及裁剪识别、分栏、来源版式、身份刷新、视觉身份、计算版本、模板复用、微调审核、保存/撤销、特殊单证分类、模板存储和管理。`git diff --check` 通过。前端和桌面接口未改动，本轮未重复其构建或测试。

模板流程测试将第一栏高度减少 1 pt，仅确认第一栏。另一份字段值不同、实际版式相同的合成 PDF 应用后，只有第一栏变化，第二、三栏保持原样；顶部字段移位的另一版式不应用该模板。
