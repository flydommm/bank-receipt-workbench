## 工程排查与现场反馈的边界

以下是合成 PDF 和临时库的工程诊断，不能替代 HX-B/HX-C 现场反馈，也不能据此断言真实任务的根因：

- 使用历史模板会强制 `needs_review`，在 `engine/batch_pdf.py:270` 的两种模式中均可复现。
- 只完成普通审核确认后，同文件、同条件重分析可以恢复旧审核，使有效待复核为 0；对应路径见 `engine/receipt_review_store.py:297-343`。关键词或模式 context 变化时不会恢复，对应模型路径见 `engine/receipt_review_models.py:290-301`。
- 重开数据库后的差异仍存在，期间没有重新保存模板。在“无风险控制”条件下，自动识别（不应用历史模板）为 0/3；历史模板 split/search 均为 3/3，且只观察到 `historical_layout_applied`。
- HX-B/HX-C 的任务诊断和数据库尚未读取，不能凭现场计数断言根因或模板框位失败。新分析恢复旧审核与本轮“只复用边界，不继承旧审核结论”的约定存在冲突，待修正；本轮只记录诊断，不改代码或新包。

- 模板只复用栏位边界，不复用旧关键词、旧文件内容或旧审核结论；尾页只应用当前页面实际存在且位置对应的栏位。
- “历史任务”只是界面入口取消；旧任务、模板记录和业务原件保留，不迁移、不清理、不覆盖。
