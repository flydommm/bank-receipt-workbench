# 交付检查清单

适用于当前 Windows x64 Core。检查结果必须绑定到实际提交和安装包，不能把旧版、源码测试或本机结果说成新版远端安装验收。

## 源码和隐私

- 明确提交、合并、推送和打包授权，核对远端 main；不强推。
- 在最终源码树检查私钥、令牌、个人路径和已知业务标识；只报告命中位置，不传播内容。
- 原始 PDF、数据库、账户档案、日志和本机验收材料不进入 Git 或源码归档。
- 本地开发历史若含未审查资料，使用审查后的完整变更整合到 main，保留原分支供恢复。
- 有效合成测试、依赖锁文件、CI 与第三方许可保留；过期手工验收记录本机归档。
- README、使用指南、应用帮助和版本元数据一致；不填写尚不存在的下载链接。

## 验证

```powershell
bun run build
bun run test:web
py -3.12 -m pytest tests
$env:PDF_SEARCH_TEST_PYTHON = (py -3.12 -c "import sys; print(sys.executable)").Trim()
cargo test --manifest-path src-tauri/Cargo.toml --locked
py -3.12 scripts/audit-public-tree.py
```

按实际变更运行对应检查；整合较多变更时应覆盖完整测试。记录退出码、测试数量、跳过和失败，不隐藏基线问题。

人工核对默认账户重置、模板保存/取消、导入预览、字段修正、导出阶段/计数/耗时、成功和失败状态。真实材料先复制并记录哈希，仅在本机验证，不提交业务内容。

## 打包与安装

使用干净的已提交源码运行 `scripts/build-release.ps1 -Edition Core`。记录版本、提交、构建命令、运行时与安装包 SHA-256；检查内嵌 Excel 模板、私有 Python 和第三方许可。源码归档与安装包应对应同一提交。

升级前保留稳定包和本机资料恢复副本。安装后检查版本、引擎连接及受影响流程。分别记录本机与远端、升级与全新安装、合成与真实样本的验证范围。

## 推送

仅推送经过审查的目标分支，不把工作分支历史、验收目录或安装包自动全部推送。推送后验证远端 main 指向预期提交，并检查可取得的 CI 结果。创建公开 Release、改仓库可见性或许可证属于不同操作，不由普通 push 隐式执行。
