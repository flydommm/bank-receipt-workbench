# 0.1.39 排除 / 恢复与导出收尾计划

依据：[用户已批准的设计](../specs/2026-09-20-receipt-exclusion-closeout-design.md)。范围为补齐当前唯一无效联的人工排除 / 恢复路径，并完成关联导出。已通过的 0.1.37 / 0.1.38 范围继续保留，不重新执行整套人工清单。

## 实施与责任

1. 审核状态与持久化：新增严格 `excluded` 状态；单条保存和恢复、任务 / 分析隔离、校准保存 / 撤销状态转移及针对性回归。后端审核代理负责。
2. 导出：权威非排除集合、未复核门控、整页 / 裁剪冲突、排除明细及冻结摘要、发布时重新验证。导出代理负责；保留旧通用导出协议行为。
3. 界面与协议：当前候选排除 / 恢复待复核、计数和按钮出现条件、写入恢复、严格摘要 / 回执解码及交互回归。前端代理负责，与导出代理共享合同。
4. 整合：主代理检查记录编解码兼容、既有计算版本隔离、原件只读及源文件 / 安装包版本一致性；独立代理按实际差异审查，修复有证据的问题后提交。
5. 一次构建 0.1.39 Core NSIS，固定源码提交、大小和 SHA-256，完成运行库隔离与最小原生集成验证。保留 0.1.38 安装包。
6. 远端升级后只检查新增流程：旧任务数据与验收证据保留；用 SH-A 26 页短新任务检查无效联排除、恢复待复核、再次排除，确认其他项不受影响；实际输出保留项，核对普通 / 特殊凭证、PDF / XLSX / 清单和原件哈希。既有计算指纹会随本次代码变化，旧任务需重新分析才能继续审核，不豁免一致性保护，也不重新确认旧四文件任务的 1246 项。记录实际结果，不用自动化结果代替安装包内操作。
7. 更新当前清单入口、0.1.39 定向验收和交付记录，提供 PDF 阅读版。未准备的条件项继续注明，不增加重复测试待办。

## 完成条件

- 当前任务可排除无效候选后导出，恢复后重新受待复核门控约束；排除不扩散，不被批量确认、校准保存或旧预览绕过。
- 代码、相关回归、独立审查、固定提交的 NSIS 与资源验证完成。
- 远端实际导出通过关联核验，原件未改变，交付记录区分已验证范围和条件限制。
