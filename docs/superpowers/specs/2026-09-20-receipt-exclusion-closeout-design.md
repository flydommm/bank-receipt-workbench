# 无效候选的人工排除与恢复（已批准）

2026-09-20 用户明确批准：“同意按此方案排除/恢复”。按本方案实施 0.1.39；0.1.38 安装包及既有验收证据保持原样。

## 已证实的问题

0.1.38 远端定向验收发现 SH-A 第 17 页第 3 栏为明确印有“此空白联无效”的区域。原生标记已识别，但同栏有独立位图，现有证据不能通用地证明图片不含正文或印章，因此保留待复核是必要的保守处理。产品没有人工排除路径；待复核门控又要求全部处理后才能导出，导致用户无法完成该任务。

本方案不降低自动检测的证据要求，不将无效联伪装成已确认的有效回单，也不改动 PDF 或删除原始候选。

## 最小行为

- 结果检查时，当前选中候选提供次级操作“排除此片段”；只作用于这一处，不按银行、版式或位置扩散。
- 排除后仍保留在任务的全部列表，显示“已排除”，可执行“恢复待复核”。恢复后须重新核对，不能直接变成已确认。
- 已排除项不计待复核、不进入 PDF/XLSX 的输出明细；未处理的其他待复核项仍隐藏导出入口。全部排除时没有导出按钮。
- 导出数量为保留项数；导出清单另列被排除项的稳定身份、来源页/栏、记录版本和决定，便于核对为什么少了一项。
- 排除属于当前任务、当前分析结果的人工决定。换关键词、重新分析或版式身份变化时，禁止无条件继承到新候选。

## 实现边界

复用现有单条审核保存通道，新增严格校验的 `excluded` 状态；保留原始身份、候选框、记录版本和事务约束。前端刷新权威结果后才显示成功，写入中禁用并发动作；丢响应后先重新读取，不能假定未写入。

导出保留完整任务作为校验依据，显式选择非排除项，使用既有 `list` 范围。银行回单的本流程必须在后端验证所选集合恰等于全部非排除项且不存在待处理项，不能仅检查是子集。后端继续拒绝将排除项直接导出，并区分“已人工排除”与“尚未复核”的省略统计。排除明细来自权威记录，纳入冻结范围、摘要解析和发布回执校验。不得只从前端数组删除候选来规避校验。

现有共享审核 context 不含任务 ID，准备审核时还会将相同原始候选记录重绑。因此人工排除必须另行检查任务条目身份及分析结果身份；新任务或重新分析不得自动继承排除。不得改动普通历史版式复用与其他已授权确认行为。

校准状态转移须显式处理：同一任务中未改变排除项身份和几何时保留排除决定；改变其候选身份或几何时恢复待复核，绝不由校准保存静默设为 confirmed。撤销校准精确恢复保存前决定。对身份和几何未变化的原排除项，显式“恢复待复核”是重新纳入的唯一操作，不借批量确认隐式恢复；身份或几何变化后的排除决定失效仍按前述规则处理。

同一来源页若有排除项而另一个保留项要求 full_page，整页图像会重新包含被排除区域。本最小方案拒绝这种导出冲突，提示用户返回审核处理，不自动改框或遮盖 PDF；同页不同裁剪框亦应检查是否实质包含已排除区域，不能只过滤身份。普通相邻边缘浮点误差按现有几何容差处理。

旧客户端严格解码器不认识新状态；需要明确该版本数据向旧版回滚的读取限制，不能静默映射成 confirmed。所有状态编解码、缓存指纹和快照恢复路径均须检查。

实施审查补充（2026-09-20）：仅在共享记录中增加状态无法保存任务隔离，已用合成 A 排除 → B 确认 → 回 A 复现静默重新确认。为实现上述已批准语义，增加 `decision_scope` 列及复合主键：普通历史记录仍使用空作用域；从首次排除开始，该条目及结果的后续恢复 / 确认决定使用独立作用域。事务迁移旧表，旧 8 列允许只读验证；旧客户端因严格列 / 主键校验拒读新结构。回滚须恢复升级前的数据副本，不将新增作用域静默忽略。此为任务隔离所必需的存储修复，不扩大用户操作范围。

## 定向验收

1. 单处排除/恢复只改变所选项的审核决定，来源哈希和其他候选几何、决定不变。
2. 有其他待复核时仍不能导出；全部处理后只输出保留项；全部排除时不生成空导出。
3. 保存冲突、重复点击、丢响应、旧会话迟到返回不得产生错误成功或覆盖新状态。
4. 排除项不能由伪造导出请求输出；创建预览后恢复/修改决定使旧预览失效。
5. SH-A 无效联明确排除后，普通回单与独立通知书/缴税凭证正常导出，PDF、XLSX 与清单数量及映射吻合。
6. 先排除再保存/撤销同版式校准，检查状态转移；新任务与重新分析不继承排除。旧版读取新增状态时安全拒读，不改写；整页与排除区域冲突时拒绝输出。
