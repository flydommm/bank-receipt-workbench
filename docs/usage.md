# 使用指南

本文面向 Windows x64 初次使用者。0.1.27 当前仍是公开发布准备版；如果你没有维护者提供的、带 SHA-256 的正式安装包，请不要从 `outputs/`、`target/` 或其他本地构建目录取包。反馈入口、候选分割与同银行联动的本次更新位于源码分支，当前 `v0.1.27-pre.1` 安装包尚未包含；安装包状态以 [GitHub Releases](https://github.com/flydommm/bank-receipt-workbench/releases) 为准。

## 安装前选择 edition

- `Core` 适合 PDF 已经包含可选择文字的情况。它包含应用私有 Python 和 PyMuPDF。
- `Ocr` 适合同时处理文字型 PDF 和扫描 PDF。它还包含本地 PaddleOCR/PaddlePaddle 运行时，体积和首次启动时间更大。

安装包使用应用私有 Python，不要求用户把 Python 加入系统 PATH。Windows 还需要可用的 WebView2 Runtime；安装器会在需要时提示处理。

扫描 PDF 的首次 OCR 初始化或识别可能下载公开模型，首次使用请允许网络访问。模型下载后，后续处理可在本地完成；模型是否已准备好可在“帮助与反馈”中点击“检测 OCR”。“OCR 已安装，待验证”只表示依赖可以导入，不表示一次识别已经成功。

## 从 PDF 到结果

1. 点击“选择 PDF”或“选择文件夹”。也可以用“添加 PDF”或“添加文件夹”把材料加入当前任务。应用只接受 PDF，并把来源加入当前任务，不会因为移除来源而删除原文件。
2. 在“包含关键词”中输入至少一个词。可添加多个包含词，选择“全部满足”或“任一满足”；也可以添加排除词，任意一个排除词命中就排除对应片段。精确匹配适合文字稳定的材料，模糊匹配可容忍部分空格、错字或 OCR 差异。
3. 点击“开始分析”。分析过程中左侧显示本轮任务和各来源状态；不要在原始文件仍被其他程序写入时开始分析。若某些文件失败，先查看失败来源和阶段，再使用“重新分析整批”或重试失败文件。
4. 在右侧命中列表选择片段。预览会显示真实页面、关键词位置和候选凭证范围。候选框只是建议，低置信度、边界不完整或版式不同的片段需要重点检查；边界正确的自动候选可以直接进入导出流程。
5. 在“结果检查”中先检查自动候选：如果绿色框完整包含回单抬头、交易内容、印章和底部末行，且没有带入相邻回单，直接点击“选择导出范围”；如果框选不合适，先选中需要调整的命中片段，再点击“进入微调”。自动边界正确时无需微调，也无需按银行逐轮确认。
6. 进入微调的准备阶段会保留你进入前选中的出具银行、位置和样本，准备完成后从该位置开始，不会跳到默认的其他栏位。随后才按出具银行、回单版式和页面位置安排审核轮次；同一家银行的多个 PDF 会合并为一个银行来源，其他银行不会联动。当前银行的剩余位置完成后再处理其他银行，每轮只需在当前轮列表中继续检查样本，系统会把严格匹配的同类候选纳入本轮。
7. 检查绿色裁剪框。拖动边框、边角或使用方向键时只更新当前调整，允许连续移动和缩放；这时不能切页、切片段或导出。调整完成后点击“确认并预览本轮 N 处”，应用会生成本轮全部候选的预览，但此时尚未应用到本轮结果。逐项查看抬头、交易内容、印章和底部末行，发现问题点击“返回调整”；检查无误后确认“保存后记住本版式框位置，供下次同版式文件参考”是否符合本次意图，再点击“保存本轮 N 处”。默认勾选，取消则只保存本轮结果，不写入历史版式参考。即使不需要调整，也通过“确认并预览本轮 N 处”检查后再保存。
8. 当前轮保存完成会同时完成确认，点击“开始下一位置微调”；如果当前银行本次选入的位置已经保存，先点击“检查本银行完成情况”，再点击“完成本银行，进入下一银行”或“完成本次微调”。也可以先点击“取消当前调整”放弃尚未预览的修改，再点击“退出微调”，返回结果页改选其他片段后重新进入。退出不会撤销已保存修改；未完成或阻塞片段仍会在导出范围校验中拦截。已保存本轮后发现不合适，可点击“撤销本轮”。
9. 无论是第 5 步直接进入范围选择，还是完成／退出微调后返回“结果检查”，都要选择全部结果、当前来源或明确的片段范围，填写输出名称，并选择：
   - 合并版：所有选中片段放入一份 PDF；
   - 按来源输出：每个来源单独生成 PDF；
   - 同时输出：生成合并版和来源版；
   - 可选 XLSX：逐条保留来源、页码、片段和审核信息，便于核对。
10. 在“最终 PDF 导出预览”中逐页查看。确认预览后选择输出目录。应用不会覆盖同名结果；请打开结果目录核对 PDF 和可选的 XLSX。

应用没有另存可搜索 PDF 的用户入口。OCR 识别结果只进入本地搜索和候选分析流程。

## 任务、目录和缓存

开始分析后，应用会保存持久任务、来源身份、搜索条件、进度、命中和审核状态；历史任务需要通过“任务历史”明确打开。暂停会在安全页边界结束，继续时保留已完成页；停止后可根据任务状态选择重新处理。

原始 PDF 不会复制回任务数据库，也不会因删除任务或清理结果而被删除。应用会在本机应用数据目录保存任务 SQLite 数据库，在应用缓存目录保存临时预览和 OCR 文字缓存。OCR 缓存包含识别出的文字和坐标，默认按大小和保留时间自动回收；帮助中心可以查看或清除它。清除 OCR 缓存不会删除原 PDF、任务、模型或已经导出的文件。

## 默认限制

当前版本默认采用以下保护上限：

| 项目 | 默认值 | 说明 |
| --- | ---: | --- |
| 单个 PDF 页数 | 5,000 页 | 元数据可以显示更大的页数，但分析和预览会按上限阻止 |
| 单次文件选择 | 500 个 PDF | 目录扫描遇到上限会停止继续收集 |
| 单个 PDF 大小 | 500 MiB | 超出后不会开始正常分析 |
| 任务数据库配额 | 2 GiB | 包括数据库、WAL 和 SHM 文件的占用估算 |

高级用户可以通过 `PDF_SEARCH_MAX_PAGES`、`PDF_SEARCH_MAX_FILES` 和 `PDF_SEARCH_MAX_FILE_BYTES` 调整相应配置。只接受十进制整数且有代码设定的安全范围；配置更高只表示允许更大的输入，不代表相应规模已经通过性能或 OCR 验证。

## 常见问题

### 多回单页面如何裁剪，怎样一起微调

进入微调默认处理待复核片段和当前选中片段。例如只有 8 张尾页待复核，选择其中一张进入后，只准备这些待复核页面。主动选中自动确认片段修边时，会另行核实它的同银行、同版式、同位置自动候选，其他已确认位置不加入本次审核。每轮请看实际处数；预览并保存 1 处不会自动处理未包含在本轮中的其余 7 处，按界面的剩余数量继续下一轮。

若当前银行显示“待核实来源”，本轮仅处理当前 1 处，不会同步其他片段；预览和保存都以界面的“本轮 N 处”为实际范围。银行标识或版式证据不足均可能导致单项处理，不能仅凭该提示判断 OCR 故障。如果回单的银行名称是图片，请在“帮助与反馈”中点击“检测 OCR”，正常后重新分析原 PDF；升级后也应重新分析旧结果，重新生成银行身份与自动候选，不能只退出再进入微调。

同一页有多张回单时，即使全部命中，也分别保留各张绿色候选框。原生每页只有一张回单的版式继续保留整页，正文只占上半页也不会据此自动裁小。多回单版式的单张尾页，会参考同一 PDF 的同版式多联页（不要求参考页命中），或明确的无效空白区域标记进行分割。首栏、中栏、末栏和只有一张回单的尾页都应抽查，确认边界没有吞入相邻回单。

自动候选与手动微调使用相同的抬头归属规则：紧邻本张标题的“打印次数”应完整留在本张框内，下一张的标记应排除在外。手续费回单与普通业务回单的文字排布可能不同，关键词只决定命中哪张回单，不应改变同一张回单的自动边界。

保存本轮后，如果本次范围已完成而你还需要修正该银行其他位置，点击“继续微调本银行其他位置”，选择位置并点击“开始所选位置微调”。无需退出再进入，也不会清除前一轮的保存和确认。其他位置正确时可以结束本次微调。

无法可靠判断原件版式时，先保留整页并标记需复核；进入微调后可以展开“当前边界不合适”，点击“按单张候选分割”，再核对绿色边框。点击“调整为整页范围”可以明确保留整页。历史任务和审核决定继续保留，不会在升级或载入时自动改写。计算版本变化后，需使用仍保留的原始 PDF 重新开始分析任务，让新版计算重建版式证据和候选边界；不需要删除来源或重新上传文件，也不能混用两种候选规则。

进入微调后，应用按同一出具银行、同一回单版式和同一页面位置组成当前轮；同一家银行的多个 PDF 可以在同一轮中同步。拖动、缩放或键盘操作都先保留为当前调整，点击“确认并预览本轮”后显示本轮预览数量；检查无误后点击“保存本轮 N 处”，样本和符合条件的同类目标一起一次性保存并确认。已经确认、单独调整或明确保留整页的候选会受到保护。不同银行、银行身份无法核实、版式不一致或位置不一致的候选会留在自己的轮次中。

确认并预览后仍需逐项检查本轮候选，再点击“保存本轮 N 处”；保存这一步会明确结束当前轮，不需要第二个确认按钮。版式检查失败时尚未应用，当前调整会保留；生成本轮预览时若样本超出凭证保护边界，提示会指出对应的上、下、左或右边以及超出的毫米数，并显示“本轮尚未保存”，可以继续调整后重试或点击“取消当前调整”，不需要移除来源或重新上传文件；审核数据库写入失败或结果不明确时，只使用“重试本轮保存”或“放弃失败操作并重新核对”，不要用取消或撤销猜测写入结果。如果已保存本轮但尚未进入下一轮，可以用“撤销本轮”一起恢复样本和同类目标，随后重新调整。已保存的裁剪框会随任务恢复，普通导出可以依据持久化且有效的审核确认；银行、位置和微调确认进度属于当前微调会话，只有重新进入微调时才需要按提示重新核对。

如果多联尾页仍显示整页范围，展开“当前边界不合适”，点击“按单张候选分割”采用单张候选，或点击“调整为整页范围”明确保留整页；之后仍要确认并预览当前轮，检查完成再保存。原生单页单栏回单可以继续保留整页，多联版式即使整页全部命中也应按单张候选检查。首栏、中栏、末栏和多联尾页都应抽查，确认绿色边框没有吞入相邻回单。

### 审核按钮应该怎么选

自动候选正确时按“结果检查 → 选择导出范围 → 最终 PDF 导出预览 → 导出”的顺序操作，无需进入微调。发现边界问题并进入微调后，按“调整 → 确认并预览 → 检查 → 保存本轮 → 下一位置 → 完成银行或退出 → 选择导出范围”的顺序操作；进入后只显示当前阶段可用的操作，当前轮的样本由用户在本轮列表中选择，位置轮次由应用自动安排。

- **调整中**：需要改框时拖动边框、边角或使用方向键，完成后点击“确认并预览本轮 N 处”；不需要改框时也使用这个按钮生成预览。“取消当前调整”只放弃尚未预览的修改。
- **本轮预览尚未保存**：查看本轮 N 处候选后，发现问题点击“返回调整”；确认无误后点击“保存本轮 N 处”。版式检查失败时本轮尚未应用；生成本轮预览时若样本超出凭证保护边界，提示会指出对应边和超出的毫米数，并显示本轮尚未保存，先修正边界或取消当前调整。审核数据库写入失败或结果不明确时使用“重试本轮保存”或“放弃失败操作并重新核对”。
- **轮次和银行**：看到“第 N 轮已保存并确认”后点击“开始下一位置微调”。当前银行本次选入的位置都保存后点击“检查本银行完成情况”，再进入下一银行或完成本次微调；也可以点击“退出微调”恢复普通检查。退出后未完成或阻塞片段仍不能通过“选择导出范围”的校验。
- **边界修复**：需要改整页或单张范围时展开“当前边界不合适”，选择对应操作后重新确认并预览、检查和保存。若刚完成的轮次需要退回，使用“撤销本轮”；它会一起恢复样本和同类目标。

绿色框应包含回单抬头、交易内容、印章和底部末行，不应侵入相邻回单。不同银行不会互相同步，银行身份、版式或位置不一致的候选会独立核对。生成本轮预览后，可以在右侧列表切换本轮片段，逐项检查联动后的框；尚未确认的拖动草稿需先确认并生成预览，才能切换片段。版式检查尚未写入失败时可返回调整或取消当前调整，审核数据库写入失败或结果不明确时请按提示重试本轮保存或放弃失败操作并重新核对。微调时可点击“查看微调说明”，直接打开帮助中的详细步骤。

### 文字型 PDF 能搜索，扫描 PDF 提示 OCR 不可用

有些文字型回单把银行名称放在独立图片标识中。OCR 版会在标题附近的小图中识别出具银行，并复用与该图片内容绑定的本地 OCR 缓存；不会把交易对手开户行或文件名当成出具银行。首次模型初始化可能较慢，后续同一标识通常无需重新识别。识别不可用或证据冲突时仍标为待核实，不跨银行同步。

请确认安装的是 `Ocr` edition，并在“帮助与反馈”中点击“检测 OCR”。如果状态是“已安装，待验证”，等待检测完成；如果首次检测需要联网下载模型，请允许模型下载后重试。`Core` edition 不包含完整 OCR 运行时，不能处理没有文字层的扫描页。

### OCR 检测通过，但某页命中或裁剪不准确

检测只验证本机可以识别应用生成的合成文字，不保证任意扫描件的识别准确率、边界质量或速度。请放大页面检查命中和绿色候选框，手动调整并逐片段确认；低置信度结果不要直接整组确认。

### 原始文件被改动后任务无法继续

应用会用文件身份和 SHA-256 核验来源。请重新选择内容完全相同的原始 PDF；不要用同名但内容不同的文件替换。导出前再次核验失败时，返回任务重新载入或重新分析。

### 导出按钮不可用

检查当前范围是否仍有未完成、阻塞、预览未完成或来源已变化的片段。自动边界正确时无需完成银行微调轮次，可以直接在“结果检查”点击“选择导出范围”；如果已经进入微调，先完成当前流程或显式点击“退出微调”，再选择范围并生成最终 PDF 导出预览。退出不会把未完成片段当作已确认，导出范围校验仍会拦截未确认或阻塞片段。

### 如何反馈问题

打开“帮助与反馈”的“03 使用反馈”，填写问题描述、复现步骤和期望结果，然后生成反馈预览。先检查预览并删除你自行填写的路径、客户名称、账号、文件名或其他敏感内容。预览只包含填写内容和应用状态摘要，不会自动附加 PDF 或日志，也不会将反馈正文写入外部链接的 URL 参数。

你可以保留原有的“复制文本”和“保存为 TXT”操作，也可以选择一个外部联系渠道：

- **复制反馈并写邮件**：应用先复制预览，再打开默认邮件客户端，收件人为 `venz@163.com`。请在正文粘贴、再次检查后手动发送；维护者通过原邮件回复。
- **复制反馈并打开 GitHub**：应用先复制预览，再打开[新建 Issue 页面](https://github.com/flydommm/bank-receipt-workbench/issues/new)。请登录 GitHub、粘贴、检查并手动提交；维护者在同一条 Issue 中回复。公开 Issue 不要包含真实银行材料或可利用的安全漏洞细节，安全问题请按 [SECURITY.md](../SECURITY.md) 的私密报告说明处理。
- **微信**：复制并添加微信号 `vinz2009`，再在微信中手动发送反馈；应用不会自动添加好友或发送消息，维护者通过微信回复。

邮件、GitHub 和微信的发送行为发生在用户选择的外部应用或网页中，应用不会自动上传反馈、创建 Issue、发送消息或附加 PDF/日志。若邮件客户端不可用、GitHub 要求登录或网络不可用，回到预览手工复制，或先保存 TXT 再在外部渠道粘贴。复制失败时也可以手工选择预览文本；应用不会提供自动提醒，也不能通过这些入口确认已成功接收，不承诺实时响应或固定响应时限。
