# 回单版式领域合同 v1

这是 [P1–P3 实施](receipt-layout-todo.md) 的领域与持久化合同。领域对象使用相同的 snake_case JSON，前端和 Python 共同读取 `tests/fixtures/receipt_layout_v1.json`。本合同落地不等于旧分析、审核、宿主已支持新模式；入口贯通与能力启用在 P3 完成。

## 数值、版本和坐标

- `schema_version` 必须是整数 `1`，未知版本或额外字段拒绝。布尔值不作为数字；几何数字采用有限 IEEE754 双精度语义，页码、修订和位置等整数身份必须在 JavaScript 安全整数范围内。
- 标识符使用 `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`；SHA-256 为 64 位小写十六进制。标识符由程序生成，不存放文件名或业务正文。
- `page_geometry` 字段为 `pdf_box`、`rotation`、`user_unit`、`width_pt`、`height_pt`。
- `pdf_box` 为原 PDF 的有效可见页框（CropBox 与 MediaBox 的交集），坐标以 PDF 底部向上为正，尚未应用 UserUnit。保留非零原点。`rotation` 为顺时针 0/90/180/270 度，`user_unit > 0`。
- `width_pt`、`height_pt` 为旋转后实际物理 point 尺寸，必须和框、旋转、单位计算一致。布局和命中框均采用此可见页面左上角向下坐标。1 英寸 = 72 point = 25.4 mm。
- 边界比较仅容纳 `64 * IEEE754 epsilon * max(1, 比较值绝对值)` 的浮点误差；不设置毫米级容差，不静默钳制裁剪。
- 最小裁剪边长为 12 point；页面本身小于 12 point 的维度只能保留该维度全长。最大栏数先按 `min(1000, floor(height_pt / min(12, height_pt)))` 校验，再生成数组；1000 是单页资源上限，不能按超大输入无限分配。

## 版式

`layout_definition` 字段：

| 字段 | 合同 |
| --- | --- |
| `schema_version` | 1 |
| `layout_id` / `revision` | 稳定 ID / 正整数修订 |
| `workspace_id` | 显式本地工作范围 ID |
| `issuer_id` / `family_id` | 已核实出具银行 / 稳定版式家族 ID；不能核实则为 null，禁止自动跨 PDF 匹配 |
| `evidence_version` | 识别依据算法 ID，不含关键词、交易值或人工框坐标 |
| `page_geometry` | 上述完整坐标合同 |
| `uniform_height` | 布尔值，开启时所有栏高度相等 |
| `left_pt` / `right_pt` | 共享左右裁去距离，非负，剩余宽度满足最小裁剪尺寸 |
| `slots` | 非空数组，按自上而下顺序，数量受页面高度约束 |

每个 slot 只有 `slot_id`、`position_index`（从 1 连续递增）、`top_pt`、`height_pt`。`slot_id` 在版式内唯一；不使用筛选后的片段序号。所有槽位必须在纸张内、正尺寸、不重叠，允许相接。未命中或尾页缺席槽位仍参与整版校验。尾页沿用原 `slots`，不按实际回单数重新等分。

初始自动定义的 `layout_id` 包含初始页面几何和槽位参数的摘要，避免相同家族中不同栏距共享实例身份。`family_id` 仅来自可核实的稳定版式证据，不含关键词或人工框坐标；编辑既有定义保留 ID、增加 revision，不能把家族身份与一个具体裁剪版本混用。

P2 的同来源参考还要求标题锚点与参考槽位一一对应，不能只凭银行/内部格式相同套用另一种栏距。物理尺寸及锚点识别比较允许 0.5 point 差异；这只是识别条件，不放宽实际裁剪纸张边界或槽位不重叠校验。只有尾页中实际存在的回单需要锚点对应，缺席栏位沿用参考定义并另行判断空白/无效。

变更影响：共享高度开关、共享左右边距、纸张、栏数、槽位身份/顺序变化影响旧新槽位的并集；保持以上参数时，比较每栏 top/height，返回实际变化槽位。仅修订号变化不代表框变化。人工独立调整或明确保留整页的目标默认为保留例外，只有显式纳入覆盖才进入新预览；自动确认不作为排除依据。

整版微调的前端临时草稿允许有限数字构成的越页/重叠状态，以便用户依次修改全部栏位；它不是可持久化的合法版式。预览前及后端继续严格校验完整纸张边界与相邻栏位，不静默缩框。选中的编辑栏位独立于本轮原始样本身份；复制尺寸保留目标位置，统一高度保留各栏起点。

2026-09-17 当前 PDF 微调范围补充：银行或版式身份未齐全时，仍禁止自动跨 PDF 匹配。在同来源内，要求工作区、页面几何、证据版本及栏位标识/位置顺序兼容；各栏顶边、底边和共享左右边距与所选样本的差异均不超过 1 point（约 0.35 mm），且双方已有的银行/版式标识不得冲突。逐页与样本比较，不传递合并。此容差仅用于准备本轮范围，不放宽提交几何校验；未改变的目标栏位保留自身几何。已核实的跨 PDF 版式规则不变。

## 页面实例与筛选

`page_result` 字段为 `schema_version`、`processing_mode`、`source_sha256`、`page`、`layout_definition`、`instances`、`excluded_slots`、`candidates`。

- `processing_mode` 仅 `search` 或 `split_all`。显式模式缺失/未知拒绝。旧任务只在专门迁移入口将缺失模式映射为 search，不用于新请求默认值。
- `page` 为从 1 开始的正整数；不把命中序号当页内位置。
- 每个槽位必须恰好对应一个实例或一个排除记录，不丢失待判断槽位。
- 实例字段：`instance_id`、`source_sha256`、`page`、`layout_id`、`layout_revision`、`slot_id`、`position_index`、`rect`、`occupancy`。
- `instance_id = receipt-v1:{source_sha256}:{page}:{layout_id}:{layout_revision}:{slot_id}`。版本、文件、页、槽位不同不能复用；关键词和命中次数不参与身份。
- 实例 rect 必须等于对应完整槽位框。`occupancy` 为 `occupied` 或 `uncertain`；无法识别的扫描槽位保留 uncertain。
- 排除记录字段 `slot_id`、`reason`，reason 仅 `blank` 或 `invalid`；不能把识别不到文字当作 blank。
- 候选字段：`instance_id`、`selection_basis`、`evidence`、`needs_review`。同一实例只出现一次候选。
- `selection_basis` 为 `keyword`、`occupied_slot` 或 `manual_slot`。search 只接受 keyword，split_all 只接受后两者。
- keyword 的 evidence 必须非空，元素只有 `query_id`（标识符）、`rect`（真实命中位置）；允许同一槽位多个命中。命中框须在页面内并与该槽位正面积相交，跨槽位时必须 needs_review。
- occupied_slot / manual_slot 的 evidence 必须为空，不伪造 match_rect。uncertain 自动候选必须 needs_review；manual_slot 表示用户明确指定有效，此时可取消该有效性待复核。
- split_all 每个实例必须有候选，包括 uncertain；search 可以零候选。明确空白/无效槽位不产生实例或候选。

## 模式校验和能力启用

新处理配置 `{processing_mode, criteria}`：search 保留非空关键词及原始条数总计 32、单项 512 Unicode 码点的限制，拒绝非字符串及孤立代理码点；两端统一使用 ECMAScript trim 空白集合、NFC 及去重。旧 API 规范化保持不变。split_all 的 criteria 必须为 null。模式切换时 UI 可保留输入草稿，但不得将旧关键词传入 split_all 处理上下文。模式/能力共享反例另见 `tests/fixtures/receipt_layout_options_v1.json`。

新增能力描述 `{contract_version: 1, processing_modes: [...], layout_schema_versions: [...]}`。新客户端使用版式实例结果前，宿主与引擎两端都必须显式声明所需 mode 和 schema；缺失字段、未知值、版本不兼容拒绝。P1 提供纯校验函数及反例；在 P3 贯通全部入口前，不向现有宿主广播尚不能执行的 split_all 能力。结果计算源清单加入新模型，以便模型改变使旧计算标识失效；领域 schema、任务结果 schema、能力版本分别维护。

## 内部持久任务与快照

以下合同已接入 Python 内部任务处理器；前端、宿主与审核写入的完整接线仍按 P3 TODO 推进，不提前开放新能力。

| 层级 | 版本与内容 |
| --- | --- |
| 任务 SQLite | `user_version=2`；每个任务单独保存 `page_result_schema` 和 `processing_options_json` |
| 旧页面检查点 | `schema=1`；旧 criteria、matches 和审核结果继续沿用原合同 |
| 新页面检查点 | `schema=2`，字段为 `schema/page/receipt_page/suggestion/diagnostics` |
| 页面领域对象 | 新检查点中的 `receipt_page.schema_version=1`；完整布局只存一次 |
| 新发布快照 | 快照 SQL 行 `schema=2`；分页结果显式返回 `schema=2`，旧分页响应不增加字段 |
| 新审核上下文 | `version=3`；来源集合、条件指纹、计算版本、完整处理选项、匹配方式 |

数据库升级先验证已知旧表结构、完整性和外键，创建独立的 `pre-v2` 备份，再在事务中升级；未知表结构、将随重建丢失的索引及未来版本拒绝迁移。失败回滚，不通过删除数据库恢复。原有审核快照、清理记录及可选预览归属保持；业务数据库不作为迁移测试材料。

`suggestion` 只保存建议依据枚举和 `needs_review`。诊断只接受已知结构化风险码、槽位/实例引用、query ID 和坐标，不存自由业务正文。搜索诊断坐标须在页面内；内容或图片风险坐标可以超出页面，以便如实说明截断风险，不能因此拒绝保存整页分析。整体诊断仍受数量、JSON 字节及节点预算约束。建议或相关诊断要求复核时，相应候选不能写成自动确认。

两种模式均保存全部物理页的检查点，包括零命中页。创建任务时冻结模式、条件及匹配方式；计算时捕获这些配置，完成后再核对，暂停不会丢弃刚完成页面的结果和已消耗预算。恢复仍校验来源 SHA、页号、结果 codec、模式、条件引用和校验和，计算版本变化要求重新分析。

新发布项仍为 `{segment, evidence, original}`。`original` 保存稳定实例/槽位/真实位置、完整版式签名、页面几何、候选框、有效性、选择依据、复核标记和分析签名；不制造 `segment_no`、`match_rect` 或置信度。项 ID 绑定任务 ID、持久来源 ID 和实例 ID，因此同 SHA 的两个逻辑来源不会相互覆盖。证据来自真实关键词；全部分割的证据为空。

发布前在同一事务中从全部已校验检查点重建预期结果，逐项比较调用方内容；调用方自己提供一致的候选框和摘要不能改变服务器计算结果。发布、条目写入、配额检查及任务完成状态作为一个事务提交。审核载入再次重建和核对清单，重定位仅改变当前访问路径，不改变逻辑来源或原始实例。每项只保存适用诊断的签名，不为每张回单复制完整页面版式和诊断集合。

## 回单审核存储合同

新审核使用独立的 `review_receipt_records_v1` 表，与旧 `review_segments_v2` 共用上下文和任务归属事务；不向旧表填造关键词字段。上下文版本仍为 3，记录与编辑的 `schema_version` 为 1。这些版本号分别标识上下文和记录合同。

只有核验来源后、由已发布持久任务提供的清单可以登记新审核上下文。普通编辑只提交实例 ID、当前结果/记录修订、原分析签名及可变审核字段；候选几何、原件 SHA、出具版式等不可变字段由后端清单取得。`candidate` 保留候选框；独立 `manual` 裁剪仍须在当前候选框内；`full_page` 明确保留整页。允许超出自动框的整版校准由 P4 的新布局与预览事务处理，不放宽普通裁剪保存。

原件清单最多 50,000 项，每项有独立 JSON 预算，完整清单另有 128 MiB 上限；条数和总字节均须满足。来源逻辑键和实例 ID 共同标识记录，同 SHA 的不同 PDF 来源互不覆盖。记录修订从 1 开始；编辑期望 0 表示尚未保存。整批校验后才写入，任一项修订冲突或写入失败使本批全部回滚。

同一来源重新分析时，仅由后端将内容与几何完全相同的旧记录绑定到新任务项 ID。分析签名变化时保留旧记录版本用于冲突检查，但不恢复旧裁剪或确认状态；同签名而几何不同视为无效绑定。受信任的重定位先校验所有旧记录，包括本次清单已省略的历史记录，再更新访问路径。

只读恢复使用 SQLite 只读连接，不新建库、不迁移、不补写来源归属或修复记录；过期结果修订和异常绑定明确拒绝。整轮预览/幂等保存/撤销仍在 P4，普通保存接口不接受旧 `group_confirmed` 语义来替代整轮确认。

## 后续预览绑定

银行多模板管理的现行规则见 [银行版式模板规则与定向复检](multi-template-rules.md)。实际版式兼容身份与用户保存的独立模板身份分开：`series_id` 标识独立模板，`id` 标识具体版本；`create` 新建系列，`update` 必须指定目标版本，不能仅按银行或版式指纹替换同组模板。公司名称不作为隔离键。多套适用时不混用边界，由用户选择后重新分析。

保存本轮首次提交时冻结模板保存动作、目标版本、名称及银行显示标签；已提交后的重试不得更换意图。银行标签仅用于显示，真实适用性仍按已核验身份、凭证类型及几何判断。旧模板及旧任务 pin 按兼容规则只读恢复；模板内容更新不会改写已固定的任务输入。

P4 的不可变预览至少绑定：snapshot/operation ID、task/context ID、mode/criteria 指纹、source SHA 集合、完整版式及修订、目标实例及最终框、审核修订、人工例外和内容风险决定。预览可渲染集合必须等于后端提交集合。任何绑定项变化使快照失效；结果未明只能查询/重试原 operation，不构造新集合。实际请求、签名及存储合同在 P3/P4 与现有审核事务一起接入，不能仅凭领域类型宣称实现了后端原子保存。
